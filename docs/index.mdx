**OData4** — это расширение конфигурации 1С:Предприятия, которое публикует данные информационной базы по протоколу
**OData v4**. Имена наборов, свойств и ключей совпадают со стандартным интерфейсом `standard.odata`, поэтому
готовые запросы и отчёты переносятся почти без правок. Расширение работает с любой конфигурацией, с БСП и без неё,
и ничего не меняет в основной конфигурации.

```http
GET https://server/base/hs/odata/v4/Catalog_Номенклатура?$select=Ref_Key,Description&$top=2
```

```json
{
  "@odata.context": "https://server/base/hs/odata/v4/$metadata#Catalog_Номенклатура(Ref_Key,Description)",
  "value": [
    { "Ref_Key": "3f2a…", "Description": "Бумага А4" },
    { "Ref_Key": "8b1c…", "Description": "Картридж" }
  ]
}
```

## Зачем, если есть standard.odata

Штатный интерфейс 1С реализует OData v3 с собственными особенностями. OData4 даёт то, чего в нём нет:

## Скорость

Большие ответы в JSON собирает внешняя компонента на Rust; если она недоступна, работает тот же код на языке 1С.
Цифры получены на файловой базе с веб-сервером Apache на той же машине:

| Замер | OData4 | standard.odata |
|---|---:|---:|
| Повторный запрос `$metadata` (5,4 МБ) | ~25 мс | ~400 мс |
| 100 тыс. документов с табличными частями | 161–229 с | 257–263 с |
| Строки табличной части с `$expand`, 1 млн строк | 39 с, первая страница | 323 с, весь миллион одним ответом |
| 1 млн записей регистра накопления, одним ответом | 134 с, 1,5 ГБ | 147 с, 3,3 ГБ |

Чтобы оценить скорость на своей базе, повторите запросы на ней: результат зависит от СУБД, веб-сервера
и состава данных. Подробнее о настройке скорости — на странице [Производительность](/admin/performance).
