description: "Вложенные объекты и табличные части в одном ответе"

---

`$expand` добавляет в ответ связанные объекты и строки табличных частей: не нужно делать отдельный запрос на каждую строку.

## Ссылки

```http
GET /hs/odata/v4/Document_РеализацияТоваровУслуг?$select=Number,Date&$expand=Контрагент($select=Description,ИНН)
```

```json
{
  "value": [
    {
      "Number": "0000-000123",
      "Date": "2026-03-14T10:22:00",
      "Контрагент": { "Description": "ООО Ромашка", "ИНН": "7701234567" }
    }
  ]
}
```

Внутри раскрытия ссылки допустимы `$select` и вложенный `$expand`.

## Табличные части

```http
GET /hs/odata/v4/Document_РеализацияТоваровУслуг?$expand=Товары($filter=Количество gt 10;$orderby=Сумма desc;$top=5;$expand=Номенклатура($select=Description))
```

Внутри раскрытия табличной части доступны `$filter`, `$orderby`, `$top`, `$skip`, `$count`, `$select` и `$expand`. Опции разделяются точкой с запятой.

<Tip>
Строки табличных частей загружаются **одним запросом на уровень раскрытия** для всей страницы, а не запросом на каждый объект. Поэтому страница из 1000 документов с `$expand=Товары` стоит несколько запросов, а не тысячу.
</Tip>

## Все связи сразу

`$expand=*` раскрывает все навигации и табличные части объекта. На документе с десятками реквизитов это сотни соединений, поэтому используйте `*` осторожно и предпочитайте явный список.

## Ограничения

| Ограничение | Значение | Ответ при превышении |
|---|---|---|
| Глубина вложенности `$expand` | 3 уровня | `400` |
| Число раскрытий в одном запросе (соединения и табличные части) | 200 по умолчанию, настраивается | `400` до выполнения |
| Элементов `$orderby`, в том числе вложенных | 32 по умолчанию | `400` |

Лимиты меняются в настройках и в профиле доступа — см. [Лимиты запроса](/security/limits).

Навигация в объект вне состава публикации не раскрывается. Строки неограниченной длины раскрытого объекта не участвуют в группировке, если `$expand` применяется поверх остатков и оборотов (см. [Регистры](/read/registers)).
