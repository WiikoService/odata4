---
title: "Быстрый старт"
description: "Установить расширение, опубликовать сервис и выполнить первый запрос за 10 минут"
icon: "rocket"
---

Понадобятся права администратора информационной базы, доступ к конфигуратору и к веб-серверу, на котором
опубликована база (Apache или IIS).

<Steps>
  <Step title="Скачайте расширение">
    Возьмите файл `OData4-<версия>.cfe` последнего выпуска на странице
    [Releases](https://github.com/wiikoservice/odata4/releases).
  </Step>
  <Step title="Загрузите расширение в базу">
    В конфигураторе: **Конфигурация → Расширения конфигурации → Добавить из файла…** и выберите `.cfe`.
    В свойствах расширения:

    - **Безопасный режим** можно оставить включённым. Тогда не подключается внешняя компонента на Rust
      (ускорение выдачи JSON) и недоступен режим прав «Привилегированный»: сервис работает на языке 1С.
      Чтобы получить полную скорость, снимите флажок.
    - **Защита от опасных действий** — снимите флажок, иначе платформа будет спрашивать подтверждение
      там, где отвечать некому, например при подключении компоненты.

    Подробнее — [Установка расширения](/install/extension).
  </Step>
  <Step title="Обновите конфигурацию базы данных">
    **Конфигурация → Обновить конфигурацию базы данных** (F7). Расширение добавляет свои регистры и справочники
    (настройки, профили, токены, журнал), поэтому без обновления сервис работать не будет.
  </Step>
  <Step title="Опубликуйте HTTP-сервисы расширения">
    **Администрирование → Публикация на веб-сервере**, флажок **«Публиковать HTTP-сервисы расширений по
    умолчанию»**. Если база уже опубликована, достаточно включить этот флажок и нажать «Опубликовать».
    Подробнее — [Публикация на веб-сервере](/install/publication).
  </Step>
  <Step title="Назначьте роли">
    Без ролей расширения сервис отвечает `403`.

    - пользователям сервиса — `OData4_Пользователь`;
    - администратору сервиса — `OData4_Администратор`.

    В конфигурациях на БСП назначайте роли через профили групп доступа, иначе БСП снимет их при следующем
    обновлении прав. Права на сами данные по-прежнему дают роли конфигурации. Подробнее — [Роли](/install/roles).
  </Step>
  <Step title="Выполните первый запрос от администратора">
    Состав стандартного интерфейса OData платформа отдаёт только администратору. Первый запрос пользователя
    с правом «Администрирование» сохраняет его снимок, после этого сервис работает и для остальных пользователей.

    ```bash
    curl -u "Администратор:пароль" https://server/base/hs/odata/v4/
    ```

    <Warning>
      Пока снимок не сохранён, пользователи без прав администратора получают `503` «Состав стандартного
      интерфейса OData не сохранён».
    </Warning>
  </Step>
  <Step title="Проверьте сервис">
    <CodeGroup>
    ```bash Служебный документ
    curl -u "user:password" https://server/base/hs/odata/v4/
    ```

    ```bash $metadata
    curl -u "user:password" "https://server/base/hs/odata/v4/\$metadata"
    ```

    ```bash Данные
    curl -u "user:password" -G "https://server/base/hs/odata/v4/Catalog_Номенклатура" \
      --data-urlencode "\$select=Ref_Key,Description" \
      --data-urlencode "\$top=5"
    ```
    </CodeGroup>

    Служебный документ перечисляет опубликованные наборы, `$metadata` описывает их типы.
  </Step>
</Steps>
