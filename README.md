Power BI, Excel и ваши интеграции читают и пишут данные 1С по современному протоколу.<br>
Ставится расширением за 10 минут: без правки конфигурации и без внешних серверов.

```http
GET /base/hs/odata/v4/Document_РеализацияТоваровУслуг
    ?$filter=Date ge 2026-01-01T00:00:00Z and Контрагент/Description eq 'Ромашка'
    &$select=Number,Date,СуммаДокумента
    &$expand=Товары($select=Номенклатура_Key,Количество,Сумма)
    &$orderby=Date desc
```

Те же имена наборов, что у стандартного `standard.odata`: `Catalog_…`, `Document_…`, `AccumulationRegister_…`, `Ref_Key`.
Переход на OData4 — это смена адреса, а не переписывание отчётов.

## Зачем

Штатный OData в 1С работает по протоколу **v3**. Современные клиенты его понимают плохо, а часть важного в нём
отсутствует. OData4 — расширение, которое добавляет в базу второй, современный интерфейс. Штатный остаётся
и продолжает работать.

|                                    | `standard.odata` | **OData4**                                                   |
| ---------------------------------- | :--------------: | :----------------------------------------------------------- |
| Протокол                           |        v3        | **v4.0 и 4.01**, JSON и CSDL XML/JSON                        |
| Power BI и Excel «Из канала OData» |  с оговорками    | **нативно**, вход по токену без пароля 1С                    |
| Агрегация на сервере (`$apply`)    |        —         | **`groupby`, `aggregate`, `filter`, `topcount`…**            |
| Пакетные запросы (`$batch`)        |      `501`       | **да**, наборы изменений — одна транзакция                   |
| Запись                             |   без защиты от гонок | **ETag и `If-Match`, безопасный повтор, проведение, движения** |
| Доступ                             |  пользователь 1С | **профили: объекты, поля, отборы строк, лимиты, частота**    |
| Токены доступа                     |        —         | **срок, отзыв, ограничение по IP**                           |
| Журнал запросов и CORS             |        —         | **да**                                                       |
| `$metadata` в тёплом сеансе        |     ~400 мс      | **~25 мс** (кэш между сеансами)                              |

## Возможности

- **Чтение.** Справочники, документы, табличные части, все виды регистров, планы, журналы, константы,
  бизнес-процессы и задачи. `$filter` с функциями, `any`/`all` и путями через ссылки, `$select`, `$expand`
  на три уровня, `$orderby`, `$count`, постраничная выдача по ключу или одним ответом.
- **Регистры.** Срезы, остатки, обороты, субконто как связанные функции, с параметром `Periodicity` для оборотов по
  месяцам, кварталам и т. д.
- **Запись по бизнес-логике 1С.** `POST`, `PATCH`, `PUT`, `DELETE` идут через объектную модель: срабатывают
  обработчики, проверка заполнения и подписки. Есть проведение и отмена проведения, наборы движений,
  сообщения пользователю с указанием поля в ответе.
- **Безопасность.** Профили доступа поверх прав и RLS 1С, токены с отзывом и IP-фильтром, лимиты запросов
  и частоты (`429`). Внутренние тексты ошибок клиенту не отдаются.
- **Скорость.** Модель строится лениво, `$metadata` кэшируется между сеансами. Необязательная компонента на Rust
  ускоряет выдачу JSON, разбор запросов и `$metadata`. Если компонента недоступна, работает код на языке 1С.
- **Эксплуатация.** Форма «Настройки OData4» с составом публикации, профилями, токенами, журналом
  и готовыми адресами для Power BI. Регламентная очистка, предупреждения об опасных настройках.
- **Универсальность.** Всё строится по метаданным: работает в любой конфигурации, с БСП и без неё.

## Быстрый старт

1. Скачайте `OData4-<версия>.cfe` со страницы [релизов](https://github.com/wiikoservice/odata4/releases/latest).
2. В конфигураторе откройте «Конфигурация → Расширения конфигурации → Добавить из файла»
   и обновите конфигурацию базы данных.
3. В публикации базы на веб-сервере включите «Публиковать HTTP-сервисы расширений по умолчанию».
4. Назначьте пользователям роль `OData4_Пользователь`, администратору — `OData4_Администратор`.
   В конфигурациях на БСП роли назначаются через профили групп доступа.
5. Откройте `http://сервер/база/hs/odata/v4/` от имени администратора. Первый такой запрос запоминает
   состав стандартного интерфейса, после чего сервис доступен и остальным.

Подробная инструкция с публикацией токенов, Power BI и проверкой —
в [документации](https://docs.wiiko.by/odata4/quickstart).

## Производительность

Замеры на файловой базе (Apache на той же машине) со 100 тыс. документов и миллионом записей в регистрах.
Выдача JSON — компонентой.

| Выгрузка                                          | OData4               | `standard.odata` |
| ------------------------------------------------- | -------------------: | ---------------: |
| Документы с табличными частями, 100 тыс. (3,5 ГБ) | **161–229 с**        | 257–263 с        |
| Строки табличной части с `$expand`               | **39 с** (страница) | 323 с (всё сразу) |
| Записи регистра накопления, 1,09 млн              | **134 с**, ответ 1,5 ГБ | 147 с, 3,3 ГБ    |
| Справочник, 100 тыс.                              | 11,2 с               | 10,7 с           |
| `$metadata`, тёплый сеанс                         | **25 мс**            | ~400 мс          |

Как ускорить большие выгрузки и где OData4 пока медленнее, честно описано в разделе
[«Производительность»](https://docs.wiiko.by/odata4/admin/performance).

## Как это устроено

```
HTTP-сервис расширения  →  маршрутизатор  →  разбор параметров  →  модель EDM по метаданным
                                                │ (язык 1С или Rust)          │
                                                ▼                             ▼
                                   планировщик → параметризованный запрос 1С → выдача OData JSON
```

- `src/cfe` — исходники расширения (XML-выгрузка конфигуратора).
- `native/odata4_core` — разбор параметров запроса, выдача JSON и CSDL на Rust, без зависимостей от 1С.
- `native/odata4_addin` — внешняя компонента Native API `OData4Native` для Windows и Linux, x86 и x64.

Значения из адреса запроса никогда не подставляются в текст запроса 1С: литералы передаются параметрами,
имена таблиц и полей берутся только из проверенной модели.

## Сборка из исходников

Готовое расширение лежит в [релизах](https://github.com/wiikoservice/odata4/releases). Собрать его самому можно так:

```powershell
# расширение: загрузить XML-выгрузку в базу и сохранить в .cfe
1cv8 DESIGNER /F <база> /LoadConfigFromFiles src\cfe -Extension OData4
1cv8 DESIGNER /F <база> /DumpCfg OData4.cfe -Extension OData4

# компонента (необязательно: собранная уже лежит в src/cfe/CommonTemplates)
powershell -NoProfile -ExecutionPolicy Bypass -File native\pack.ps1
```

Для компоненты нужны Rust 1.87+, mingw-w64 для Windows, а для Linux — `zig` и `cargo-zigbuild`.
