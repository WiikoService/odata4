# История изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [1.0.1] — 2026-10-25

Поддержка платформы 8.3.20 и ленивая очистка вместо регламентного задания.

### Платформа
- Расширение устанавливается и работает на платформе **8.3.20**. Версия 1.0.0 на 8.3.20 не загружалась
  («Для использования этой конфигурации требуется более новая версия платформы»).
- Минимальная поддерживаемая платформа — 8.3.20. Более ранние версии не проверялись.

### Ленивая очистка
- Регламентного задания «Очистка OData4» больше нет: платформа 8.3.20 не разрешает расширению собственные
  регламентные задания.
- Очистку запускает сам сервис. Запрос не чаще раза в час проверяет, была ли очистка за последние сутки, и если нет —
  запускает фоновое задание «Очистка OData4». Шаги прежние: журнал старше срока хранения, счётчики частоты,
  токены продолжения, ответы повторяемых запросов.
- Очистка не зависит от сеанса обработки регламентных заданий и одинаково работает в файловой и клиент-серверной
  базе.
- Фоновое задание выполняется с правами пользователя запроса. Поэтому очистку запускают запросы пользователя с
  правами на служебные регистры OData4, например с ролью «OData4: администратор». Если к сервису обращаются только
  обычные пользователи, очищайте журнал кнопкой «Очистить старые записи» в форме настроек или вызовите
  `OData4_Очистка.ВыполнитьЗадание()` из регламентного задания основной конфигурации.
- При обновлении с 1.0.0 регламентное задание «Очистка OData4» удаляется из базы автоматически.

### Исправления
- `$apply`: `sum` и `average` на 8.3.20 обрезались до разрядности поля (сумма упиралась в `999999.9999` у
  `Число(10,4)`, среднее теряло дробные знаки). Теперь агрегат считается с полной точностью на всех платформах;
  у `average` стало больше знаков после запятой и на 8.3.27.
- `$metadata`: `ExchangeDate` у планов обмена объявляется, только если его объявляет `standard.odata` этой
  платформы (8.3.27 — да, 8.3.20 — нет).
- Текст ошибки «Тело записи — не JSON» одинаков на всех платформах: 8.3.20 называл поток чтения потоком записи.

### Проверено
- Платформы **8.3.20.1549** и **8.3.27.1719**, Windows x64, веб-сервер Apache 2.4.
- Конфигурация «Бухгалтерия для Беларуси» 2.1.55.8 (режим совместимости 8.3.14), файловая база.
- На каждой платформе: 295 модульных тестов в 1С и 339 тестов сверки выдачи и `$metadata` с `standard.odata`
  (5 пропущены: им нужен выключенный безопасный режим расширения или особая настройка ролей); Rust-компонента
  проверена отдельно на 8.3.20 без безопасного режима.

## [1.0.0] — 2026-10-01

Первый публичный релиз.

### Чтение
- Служебный документ и `$metadata` (CSDL XML 4.0 и CSDL JSON) с именами `standard.odata`.
- Справочники, документы, табличные части, планы видов характеристик, счетов и видов расчёта, планы обмена,
  бизнес-процессы, задачи, константы, журналы документов, регистры всех видов.
- `$filter` с функциями, `any`/`all`, `in` и путями через ссылки; синтаксис v3 (`substringof`, `datetime'…'`, `guid'…'`).
- `$select`, `$expand` ссылок и табличных частей (до трёх уровней), `$orderby`, `$top`, `$skip`, `$count`.
- Постраничная выдача по ключу (`@odata.nextLink`, `Prefer: odata.maxpagesize`) или одним ответом.
- Виртуальные таблицы регистров: `SliceLast`, `SliceFirst`, `Balance`, `Turnovers`, `BalanceAndTurnovers`,
  `ExtDimensions`, `RecordsWithExtDimensions`, параметр `Periodicity`.
- Агрегация `$apply`: `filter`, `groupby`, `aggregate`, `compute`, `topcount`, `bottomcount`, цепочки шагов.

### Запись
- `POST`, `PATCH`, `PUT`, `MERGE`, `DELETE` через объектную модель с бизнес-логикой конфигурации.
- Проведение и отмена проведения (`Post`, `Unpost`), наборы движений регистров, константы, регистры сведений.
- ETag, `If-Match` и `If-None-Match`, повторяемые запросы (`Repeatability-Request-ID`, `Idempotency-Key`).
- `$batch` в форматах `multipart/mixed` и JSON; набор изменений выполняется одной транзакцией.

### Доступ и эксплуатация
- Роли расширения, профили доступа (объекты, операции, поля, отборы строк, лимиты, частота).
- Токены доступа: срок действия, отзыв, ограничение по IP, отдельная публикация `odatat`.
- Базовые лимиты запроса, CORS, журнал запросов, регламентная очистка.
- Форма «Настройки OData4».

### Производительность
- Ленивая модель, кэш `$metadata` между сеансами.
- Внешняя компонента на Rust для Windows и Linux (x86, x64): разбор параметров, выдача JSON, разбор тел,
  вывод `$metadata`. При её недоступности работает код на языке 1С.
